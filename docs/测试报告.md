## 2. 测试环境与方法

### 2.1 环境

| 项 | 值 |
| --- | --- |
| 操作系统 | Windows |
| Python | 3.10+（网关与面板只用标准库；`playwright` 仅积分采集与浏览器自检需要） |

| 验证器 | headless Chrome（截图像素核对）+ Node `fs` 静态分析 + Node 原生 `fetch` 端口探测 + `curl` |

### 2.2 方法

**(a) 静态审计** —— 用 Node `fs` 逐字符扫描每个 Python 模块（跟踪三引号、单双引号转义、`#` 注释，只统计代码层括号），确认无未闭合；解析全部本地 import；把 `static/app.js` 里所有 `apiGet/apiPost` 路径与 `core/wb_gateway.py` 的分支表双向比对；校验 `static/` 文件清单与 `manifest.webmanifest` JSON。

**(b) 前端冒烟** —— 用 headless Chrome 承载**真实的** `static/index.html` + `app.css` + `app.js`，把后端 20 个接口用 `window.fetch` 桩按真实返回结构构造，跑 45 项断言：11 视图渲染、导航/主题/实时开关/抽屉、按钮点击后的**请求方法与请求体**、500/401 错误分支、hash 路由、实时日志原地更新。

**(c) 在线自检** —— `scripts/selfcheck.py --online` 对**已在运行**的服务打 16 个端点（它不会自己起服务）。

**(d) 真实上游** —— `curl` 打 `/v1/chat/completions` 验证网关 → 上游整条链路。

## 5. 风险与已知限制

### 5.1 `playwright` 是可选的

只有 `core/wb_credits_fetcher.py`（积分采集）和 `scripts/browser_check.py`（浏览器自检）需要它：`pip install playwright` 再 `python -m playwright install msedge`。网关、面板、任务、签到全部只用标准库。

### 5.2 数据前提（缺失时页面显示空态，属正常）

| 文件 | 缺失时的影响 |
| --- | --- |
| `wb_data/tasks_log.jsonl` | 「签到日志」页暂无记录，跑过任务/签到后才产生 |
| `data/models.json` | 模型页只用内置目录，「上游发现 / 手工覆盖」计数为 0 |
| `data/usage.json` | Token 统计从 0 开始，有流量后自动落盘 |
| `auths/` | 概览显示 0 个账号，去「账号管理 → 扫码登录」 |

### 5.3 桩数据的观感现象（非界面缺陷）

2026-10-17 那轮冒烟用的是模拟后端：Token 表曾出现「成功率 759%」、账号池多出灰色「停用」徽章 —— 都是桩数据与真实字段不成比例造成的，真实后端不会出现。

### 5.4 其它

- Service Worker 仅在 `http(s)` 下注册，PWA/离线缓存必须用 `http://127.0.0.1:7863/panel/` 访问。
- 面板「设置 → API Key」只写入浏览器 `localStorage`；**服务端**密钥在 `config.json` 的 `api_key`，改完需重启服务。
- 老控制台 `http://localhost:8789/` 会 302 跳到统一面板，老界面保留在 `/legacy`。

## 7. 测试台（可复现）

`devtools/_smoke_runner.js` 是冒烟 runner 源码（断言、mock 契约、5 段流程），**唯一需要维护的源**。

**方法学教训（下次直接避开）**：

1. **断言必须校验「分母」**：侧栏导航那段最初写成 `view().parentNode.querySelectorAll('#nav .nav-item')`，而 `#nav` 是 `.main` 的**兄弟**节点 → 命中 0 项却「通过」（空断言）。改成 `document.querySelectorAll(...)` 后实测 11 项。
2. **不要对数组用 `String()`**：mock 里的 `log` 是数组，`String(log) + 换行 + …` 会把 10 行用逗号拼成 1 行。改为 `Array.isArray(lg) ? lg.push(...) : …`。
3. headless 截图工具对 `(源文件, 宽, 高)` 做结果缓存 → 想重拍必须换文件名或换尺寸。
4. 截图工具的等待窗口约 2.5 秒，跑不完全部断言 → 必须把冒烟**分段**（本报告即 5 段）。

## 8. 真机试跑发现并修复的问题（2026-10-17，已修入源码）

### 8.1 两个 500 崩溃

| 症状 | 根因 | 修复 |
| --- | --- | --- |
| `GET /v1/models` → `UnboundLocalError: cannot access local variable 'urlparse'` | `_do_GET_inner()` 里有函数内局部 `import urllib.parse`，Python 因此把 `urlparse` 当局部名，而在 import 之前就调用了它。同样影响 `GET /api/credits/live` | 删掉函数内局部 import，改用模块级 `from urllib.parse import urlparse, parse_qs, quote`（`core/wb_gateway.py:29`） |
| `GET /panel/api/usage?range=7d` → `KeyError: 0` | `summary()` 的分桶有的是 list、`by_account` 是 dict，而 `_finalize_map()` 一律按整数下标索引 | `_finalize_map()` / `_finalize_series()` 同时容忍两种形状（`bucket.get(name)` 或 `bucket[index]`） |

### 8.2 四条体验问题

**①「登录成功了还一直提示等待登录」** —— `wb_auth.login_poll()` 完成时返回体**没有 message 字段**，前端只在 `d.message` 存在时才覆盖文案。修复：前端只在 `!d.done && d.message` 时写 message，done 时改写成「登录成功：昵称 · 区域 · 凭据到期 YYYY-MM-DD。凭据已写进 auths/，账号池已刷新。」并补昵称、区域徽章、`UID … · 文件名`，完成态补「关闭」按钮。

**②「切换账号有提示，但没有明确标识」** —— 概览页与账号页各加一张**「当前派发账号」卡**（昵称 / 区域 / 状态徽章 / UID / 积分余额 / 上次使用 / 上次派发原因）；账号池状态列改四态 `正在派发` / `备用可派发` / `暂不可用` / `已停用（不派发）`。

**③「不知道花的是哪个账号的积分」** —— 界面：Token 统计页「按账号（花的是谁的积分）」卡，后端把 `by_account` 的 label 从 uuid 回填成昵称；接口：聊天响应新增 `X-WorkBuddy-Account` / `-Account-Id` / `-Region` / `-Model` 四个响应头（昵称经 URL 编码，`http.server` 只接受 latin-1）。顺带修掉**上游 401**：旧逻辑不分区域一律打 `https://copilot.tencent.com`，拿 `www.workbuddy.ai`（国际版）的 token 打国内域名 → `openresty 401`。现在 `chat_upstream_url(account)` 按区域分流，并且 `_handle_chat_completions` **最多换 3 个账号重试**（401/403 视为该号凭据不可用 → `record_failure` + `AUTH_FAIL_COOLDOWN=600s` → 换下一个），全部失败才回 503。

**④「启用和已启动没有区分」** —— 全站状态词改成互不重叠的三套：模型 `会派发` / `不派发`；账号 `正在派发` / `备用可派发` / `暂不可用` / `已停用（不派发）`；采集进程 `已启动 · 运行中` / `未启动` / `采集不可用`。

### 8.3 顺手修的两个显示缺陷

- **积分列显示「1216.2%」**：原先算的是 `credits / energy`（量纲不同）的百分比 → 改成积分与能量分两行（`9,000` + 灰字 `能量 740`）。
- **账号池页昵称取不到**：`accountById()` 只查 `state.pool.accounts`，而实际数据在 `state.pool.status.accounts` → 改为依次查三处，并用 `live_credits.accounts` / `auth_files.accounts` 兜底。
